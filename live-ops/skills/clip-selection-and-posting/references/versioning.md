# Versionieren

`<root>` ist das clip-pipeline-Repo, der Ordner mit `clip-forge` und `live-ops`.

- „Push alle Änderungen“ / „merge commit und push“: die Live-Skripte liegen im Scratch-Ordner, nicht im Repo. Vor dem Commit nach `<root>/live-ops/` kopieren (`live/` ← scratch/live/*.py,*.sh; `posting/` ← scratch/pw/*.py, post_all.sh), auf Schlüssel greppen, `.gitignore` mit `*.mp4`, `*.mp3`, `.DS_Store` und der lokalen Konfig-Datei, dann commit + push auf `main`. Gibt es nur `main` und ist `origin/main` gleich, ist kein Merge nötig: das dem User so sagen und nur synchronisieren.
- Den Skill selbst NICHT als `SKILL.md` ins Repo kopieren: `video/clip-pipeline` ist ein Symlink ins Repo, eine zweite `SKILL.md` mit gleichem Namen unter `live-ops/skills/…` macht den Skillnamen mehrdeutig („Ambiguous skill name“), und skill_view/skill_manage verweigern dann den Kurznamen. Snapshot als `SKILL.snapshot.md` ablegen (`cp ~/.hermes/skills/video/clip-selection-and-posting/SKILL.md <repo>/live-ops/skills/clip-selection-and-posting/SKILL.snapshot.md`, nie als `SKILL.md`; Namenskonflikt tritt sofort nach dem nächsten Sync-Commit auf, wenn man es falsch kopiert) und Skills immer mit dem Pfad `video/clip-selection-and-posting` ansprechen. Taucht im Repo trotzdem ein `live-ops/skills/*/SKILL.md` auf (Symptom: „Ambiguous skill name"), dort `git mv SKILL.md SKILL.snapshot.md`, committen, pushen. Vor jedem Sync-Commit mit `ls live-ops/skills/*/` prüfen, dass die Datei nicht als `SKILL.md` mitkopiert wurde.
